Accessibility Statement

Last assessed: 14 March 2026

Pelangi Capsule Hostel is committed to ensuring digital accessibility for all visitors, including people with disabilities. We continually improve the user experience for everyone and apply the relevant accessibility standards to our website.

Conformance Status

We aim to conform to the Web Content Accessibility Guidelines (WCAG) 2.2 Level AA. These guidelines explain how to make web content more accessible to people with a wide range of disabilities, including visual, auditory, physical, speech, cognitive, language, learning, and neurological disabilities.

Target standard: WCAG 2.2 Level AA

Current status: Partially conformant

Last assessment date: 14 March 2026

“Partially conformant” means that some parts of the content do not yet fully conform to the accessibility standard. We are actively working to address these gaps.

Technical Specifications

Accessibility of this website relies on the following technologies to work with the particular combination of web browser and any assistive technologies or plugins installed on your computer:

  • HTML
  • WAI-ARIA
  • CSS
  • JavaScript

What We Do

We take the following measures to ensure accessibility of our website:

  • Use semantic HTML elements to ensure proper document structure
  • Provide text alternatives for non-text content such as images
  • Ensure sufficient colour contrast ratios across the site
  • Support keyboard navigation for all interactive elements
  • Use ARIA labels and roles where native HTML semantics are insufficient
  • Support text resizing up to 200% without loss of content or functionality
  • Provide visible focus indicators for interactive elements
  • Ensure the site works with common screen readers

Audio Control Policy (SC 1.4.2)

WCAG 2.2 SC 1.4.2 (Level A) requires that any audio playing automatically for more than 3 seconds must be pausable, stoppable, or have its volume controllable independently of the system volume.

Audit result: Fully compliant

  • No audio or video plays automatically on any page.
  • The YouTube check-in guide on the /check-in page uses a click-to-play facade: the iframe is not loaded until the user explicitly clicks the play button. No audio plays without user initiation.
  • The embedded YouTube video on the /gallery page does not include autoplay=1 in its source URL. Audio only plays after the user presses the play control within the iframe.
  • Google Maps embeds on the /location and /getting-here pages do not produce any audio.

Policy: Future audio content

Any future addition of auto-playing audio or video — such as lobby ambience, promotional clips, or virtual tours — must provide a visible pause or stop control within 3 seconds of page load, or must be muted by default with the user able to unmute. Auto-playing audio that cannot be controlled by the user is prohibited. All video or audio content must be reviewed against SC 1.4.2 before deployment.

Assessment Approach

We assess the accessibility of our website through the following methods:

  • Self-evaluation using automated accessibility testing tools
  • Manual testing with keyboard-only navigation
  • Testing with screen reader software
  • Lighthouse accessibility audits
